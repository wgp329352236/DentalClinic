# 部署说明（管理端 Server + Client）

本文档说明如何把 `panel/XianTong` 下的后端（Ktor/Server）与管理端前端（Vben/Client）部署到 Linux 服务器。

## 1. 部署拓扑

```
                    ┌──────────────────────────────────────┐
  浏览器 / 小程序 ──▶│ Nginx (80/443)                       │
                    │   /           → apps/web-antd/dist   │
                    │   /api/admin  → 127.0.0.1:8080       │
                    │   /api/v1     → 127.0.0.1:8080       │
                    └───────────────┬──────────────────────┘
                                    │
                            ┌───────▼────────┐
                            │ Ktor Server    │ :8080
                            └───┬────────┬───┘
                                │        │
                      PostgreSQL│        │Redis
                         :5432  │        │:6379
```

- 管理端与后端通过同一域名访问（`VITE_GLOB_API_URL=/api`），不存在跨域问题。
- Redis 用于管理端 Refresh Token 与登录失败锁定，**管理端登录强依赖 Redis**。

## 2. 环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | 21 | `server/build.gradle.kts` 使用 `jvmToolchain(21)` |
| PostgreSQL | 15+ | 表结构与种子数据由服务启动时自动创建 |
| Redis | 6+ | 通过 `REDIS_HOST` / `REDIS_PORT` / `REDIS_DATABASE` / `REDIS_PASSWORD` 注入，默认 `localhost:6379/0` 无密码 |
| Node.js（构建机） | `^20.19` / `^22.18` / `^24` | 仅前端构建需要 |
| pnpm | ≥ 10 | 前端构建需要 |
| Nginx | 任意稳定版 | 静态托管 + 反向代理 |

> 构建机与运行机可以分离：前端构建产物是纯静态文件，后端产物是一个 fat jar。

## 3. Server 部署

### 3.1 创建数据库

```bash
psql -U postgres -c 'CREATE DATABASE dental_clinic;'
```

表、索引、增量迁移与种子数据都在服务启动时自动完成，不需要手工执行 DDL。

可选：导入演示数据（仅用于测试环境）

```bash
psql -U postgres -d dental_clinic -f server/demo-data.sql
```

### 3.2 打包

```bash
cd panel/XianTong
./gradlew :server:buildFatJar
```

产物：`server/build/libs/server-all.jar`。

上传并准备目录：

```bash
mkdir -p /opt/dentalclinic/{uploads,logs}
cp server-all.jar /opt/dentalclinic/
chmod 600 /opt/dentalclinic/apiclient_key.pem   # 微信支付商户私钥
```

说明：
- 上传的图片会写入 `<进程工作目录>/uploads`（见 `FileUploadService`），所以启动时必须固定工作目录。
- `uploads/` 是唯一有状态的目录，必须可写并纳入备份。

### 3.3 配置环境变量

生产环境必须设置 `APP_ENV=prod`。启动预检（`StartupPreflight`）会在启动阶段一次性校验以下配置，任何一项缺失或仍是开发默认值都会**直接阻止启动**。

直接使用现成模板（推荐，格式同时兼容 systemd `EnvironmentFile` 与 shell `source`）：

```bash
cp panel/XianTong/server/.env.prod.example /etc/dentalclinic/server.env
chmod 600 /etc/dentalclinic/server.env
vi /etc/dentalclinic/server.env     # 逐项填值，空值项会导致启动失败
```

模板文件：`server/.env.prod.example`。

> 本地已有一份填好数据库与微信小程序凭证的 `server/.env.prod`（已被 `server/.gitignore` 忽略），可直接 `scp` 到服务器 `/etc/dentalclinic/server.env`，再补齐 JWT、微信支付、腾讯云短信等空值项。

也可以直接在命令行注入（适合临时排障，systemd 场景请用上面的模板）：

```bash
export APP_ENV=prod

# 数据库
export DB_URL='r2dbc:postgresql://127.0.0.1:5432/dental_clinic'
export DB_USERNAME='dental'
export DB_PASSWORD='<强口令>'

# Redis（支持环境变量注入，未设置时回落 localhost:6379/0 无密码）
export REDIS_HOST='127.0.0.1'
export REDIS_PORT='6379'
export REDIS_DATABASE='0'
export REDIS_PASSWORD=''          # 无密码留空即可

# 密钥（每个独立生成）
export ADMIN_JWT_SECRET="$(openssl rand -hex 32)"
export USER_JWT_SECRET="$(openssl rand -hex 32)"
export CHECKIN_SIGNING_SECRET="$(openssl rand -hex 32)"
export PHONE_ENCRYPTION_KEY="$(openssl rand -hex 32)"
export PHONE_BLIND_INDEX_KEY="$(openssl rand -hex 32)"

# 微信小程序
export WECHAT_APP_ID='...'
export WECHAT_APP_SECRET='...'
export WECHAT_WXA_ENV_VERSION='release'   # release / trial / develop

# 微信支付 V3
export WECHAT_MCH_ID='...'
export WECHAT_API_V3_KEY='...'
export WECHAT_MERCHANT_SERIAL='...'
export WECHAT_PRIVATE_KEY_PATH='/opt/dentalclinic/apiclient_key.pem'
export WECHAT_PAY_NOTIFY_URL='https://admin.example.com/api/v1/recharge/notify'   # 必须公网 HTTPS

# 腾讯云短信
export TENCENT_SMS_SECRET_ID='...'
export TENCENT_SMS_SECRET_KEY='...'
export TENCENT_SMS_SDK_APP_ID='...'
export TENCENT_SMS_SIGN_NAME='...'
export TENCENT_SMS_TEMPLATE_ID='...'
export TENCENT_SMS_REGION='ap-guangzhou'

# 推荐分享域名（非阻断项，缺失时邀请链接是死链）
export REFERRAL_SHARE_BASE_URL='https://admin.example.com'
```

变量清单与含义的权威来源：

- `server/.env.local.example`（本地模板）
- `server/src/main/resources/application-prod.yaml`（生产配置骨架）
- `server/src/main/kotlin/common/config/StartupPreflight.kt`（阻断项与告警项）

> 生产环境的凭证只通过环境变量或密钥管理服务注入，不要写进 `application-prod.yaml`，也不要提交 `.env.local`。

### 3.4 启动

```bash
cd /opt/dentalclinic
java -jar server-all.jar -config=application-prod.yaml -port=8080 \
  > logs/server.log 2>&1 &
```

首次启动会自动执行：建表 → 增量列迁移 → 种子数据 → 启动定时任务。

验证：

```bash
curl -s http://127.0.0.1:8080/    # 期望输出：Dental Clinic API
```

种子数据会创建默认管理员 `admin / admin123`，**上线后请立即修改密码**。

### 3.5 使用 systemd 托管（推荐）

`/etc/systemd/system/dentalclinic.service`：

```ini
[Unit]
Description=Dental Clinic Server
After=network.target postgresql.service redis.service

[Service]
Type=simple
WorkingDirectory=/opt/dentalclinic
EnvironmentFile=/etc/dentalclinic/server.env
ExecStart=/usr/bin/java -jar /opt/dentalclinic/server-all.jar -config=application-prod.yaml -port=8080
Restart=always
RestartSec=5
StandardOutput=append:/opt/dentalclinic/logs/server.log
StandardError=append:/opt/dentalclinic/logs/server.log

[Install]
WantedBy=multi-user.target
```

```bash
chmod 600 /etc/dentalclinic/server.env   # 存放 3.3 中的环境变量（每行 KEY=VALUE，不带 export）
systemctl daemon-reload
systemctl enable --now dentalclinic
systemctl status dentalclinic
```

## 4. Client（管理端）部署

### 4.1 构建

```bash
cd panel/XianTong/client
pnpm install --frozen-lockfile
pnpm -F @vben/web-antd run build
```

产物：

- `apps/web-antd/dist/`：静态站点
- `apps/web-antd/dist.zip`：同内容压缩包（`VITE_ARCHIVER=true`）

构建参数来自 `apps/web-antd/.env.production`，默认即可用于生产：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `VITE_BASE` | `/` | 部署在根路径 |
| `VITE_GLOB_API_URL` | `/api` | 由 Nginx 反代到后端 |
| `VITE_ROUTER_HISTORY` | `hash` | 路由为 hash 模式，刷新不会 404 |
| `VITE_COMPRESS` | `gzip` | 构建时生成 gzip 文件 |

### 4.2 发布静态文件

```bash
rsync -av --delete apps/web-antd/dist/ user@server:/var/www/dentalclinic/
```

### 4.3 Nginx 配置

`/etc/nginx/conf.d/dentalclinic.conf`：

```nginx
server {
    listen 443 ssl;
    server_name admin.example.com;

    ssl_certificate     /etc/nginx/ssl/admin.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/admin.example.com.key;

    root  /var/www/dentalclinic;
    index index.html;

    client_max_body_size 10m;    # 图片上传限制为 5MB，留出余量

    gzip on;
    gzip_min_length 1k;
    gzip_types text/css application/javascript application/json image/svg+xml;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass         http://127.0.0.1:8080;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}

# HTTP 跳转 HTTPS
server {
    listen 80;
    server_name admin.example.com;
    return 301 https://$host$request_uri;
}
```

```bash
nginx -t && nginx -s reload
```

### 4.4 Docker 方式（可选，需先修正 Dockerfile）

`client/scripts/deploy/Dockerfile` 是从 Vben 模板继承的，其中复制的仍是 `playground/dist`，本项目没有该目录，**直接构建会得到空站点**。使用前需要两处修改：

```dockerfile
# 原： RUN pnpm run build --filter=\!./docs
RUN pnpm -F @vben/web-antd run build

# 原： COPY --from=builder /app/playground/dist /usr/share/nginx/html
COPY --from=builder /app/apps/web-antd/dist /usr/share/nginx/html
```

构建与运行：

```bash
cd panel/XianTong/client
docker build -f scripts/deploy/Dockerfile -t dentalclinic-admin .
docker run -d --name dentalclinic-admin -p 8010:8080 dentalclinic-admin
```

注意：容器内的 `scripts/deploy/nginx.conf` 只做静态托管，不包含 `/api` 反向代理，生产建议仍由宿主机 Nginx 统一入口。

## 5. 验证清单

```bash
# 1. 后端存活
curl -s http://127.0.0.1:8080/

# 2. 管理端登录（走 Redis + 数据库）
curl -s -X POST http://127.0.0.1:8080/api/admin/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'

# 3. 前端页面
curl -sI https://admin.example.com/

# 4. 反向代理链路（返回 JSON 而不是 502/404）
curl -s https://admin.example.com/api/v1/clinics
```

功能自查：

- 管理端能登录、菜单正常渲染
- 图片上传成功且可预览（验证 `uploads/` 可写）
- 小程序登录、手机号授权、签到码、优惠券推广码可用（验证微信凭证）
- 验证码短信可真实下发（验证腾讯云短信凭证）

## 6. 升级与回滚

```bash
# 1. 备份（必做）
pg_dump -U dental -h 127.0.0.1 dental_clinic > backup_$(date +%F).sql
tar czf uploads_$(date +%F).tar.gz -C /opt/dentalclinic uploads

# 2. 替换产物
systemctl stop dentalclinic
cp server-all.jar /opt/dentalclinic/server-all.jar.new && mv /opt/dentalclinic/server-all.jar.new /opt/dentalclinic/server-all.jar
rsync -av --delete apps/web-antd/dist/ user@server:/var/www/dentalclinic/

# 3. 启动并观察
systemctl start dentalclinic
tail -f /opt/dentalclinic/logs/server.log
```

注意：启动时的增量迁移可能包含不可逆变更（例如删除 `user.primary_clinic_id` 列）。升级前必须完成数据库备份，确认无误后再继续。

回滚方式：恢复旧 jar + 恢复数据库备份 + 回退前端静态文件。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动即退出，日志有「启动预检未通过」 | `APP_ENV=prod` 下必填项缺失或仍为开发默认值，按日志逐项补齐 |
| 管理端登录 500 / 超时 | Redis 未启动或地址配置错误。用 `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` 指定（见 3.3），未设置时回落 `localhost:6379` |
| 页面接口 502 | Nginx 未代理 `/api/`，或后端未监听 8080 |
| 上传成功但图片裂图 | 未代理 `/api/v1`，或 `uploads/` 不可写、工作目录不对 |
| 前端路由刷新 404 | 缺少 `try_files $uri $uri/ /index.html`（本项目为 hash 路由，通常不会出现） |
| 分域名部署时浏览器报 CORS | 后端 CORS 仅放行 localhost 端口；需在 `Routing.kt` 的 `install(CORS)` 中加入正式域名后重新打包 |
| 小程序扫码提示「页面不存在」 | `WECHAT_WXA_ENV_VERSION` 与实际投放版本不一致，或小程序未发布/上传体验版 |
