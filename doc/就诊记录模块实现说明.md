# 就诊记录模块实现总结

## 📦 已实现的功能

### 1. 用户端就诊记录查询 API

**文件**: `user/service/MedicalRecordService.kt`  
**文件**: `user/route/UserMedicalRecordRoutes.kt`

实现了完整的就诊记录查询功能：
- ✅ `GET /api/v1/medical-records` - 获取就诊记录列表（分页）
- ✅ `GET /api/v1/medical-records/{id}` - 获取就诊记录详情

**功能特性**:
- 只展示已完成的就诊记录（status = "completed"）
- 按预约日期倒序排列
- 包含诊所、医生、科室信息
- 显示诊断结果和治疗方案
- 关联消费记录，计算总消费金额
- 详情页包含医生介绍和完整消费明细

---

### 2. 管理端就诊记录管理 API

**文件**: `admin/route/BusinessRoutes.kt` (appointmentAdminRoutes 函数)

实现了预约详情查看和病历编辑：
- ✅ `GET /api/admin/appointments/{id}` - 查看预约详情（含病历）
- ✅ `PUT /api/admin/appointments/{id}/medical-record` - 编辑病历摘要

**功能特性**:
- 查看完整的预约信息、用户信息、消费统计
- 编辑诊断结果（diagnosis）和治疗方案（treatmentPlan）
- 支持部分更新（可只更新其中一个字段）
- 自动记录操作审计日志

---

### 3. 数据库表结构扩展

**文件**: `admin/entity/AdminTables.kt`

在 Appointments 表中新增字段：
```kotlin
val diagnosis = text("diagnosis").nullable()         // 诊断结果/电子病历摘要
val treatmentPlan = text("treatment_plan").nullable() // 治疗方案
```

**特点**:
- 两个字段均为 TEXT 类型，支持长文本
- 可为空（nullable），不影响现有数据
- SchemaUtils.create 会自动添加新列

## 🗄️ 数据关联关系

```
Appointments (预约表)
    ├─ Users (用户表) - userId
    ├─ Clinics (诊所表) - clinicId
    ├─ Doctors (医生表) - doctorId
    ├─ Departments (科室表) - departmentId
    └─ ConsumptionRecords (消费记录表) - appointmentId
```

就诊记录通过 `appointmentId` 关联消费记录，可以查询该次就诊的所有消费明细。

## 🔐 权限配置

需要在系统中配置以下权限代码：

| 权限代码 | 权限名称 | 用途 |
|---------|---------|------|
| appointment:view | 查看预约 | 查看预约详情和病历 |
| appointment:update | 更新预约 | 编辑病历摘要（已有） |

## ⚠️ 注意事项

1. **隐私保护**: 就诊记录包含敏感医疗信息，需符合《医疗机构病历管理规定》
2. **数据隔离**: 用户端接口通过 JWT token 中的 userId 确保只能查看自己的记录
3. **权限控制**: 管理端病历编辑需要 `appointment:update` 权限
4. **审计追踪**: 所有病历编辑操作都会记录在审计日志中
5. **性能优化**: 列表查询使用分页，避免一次性加载大量数据
