## 2. 环境准备

### 2.1 启动后端

```bash
cd panel/XianTong
./gradlew :server:run
```

- 默认监听 `8080`。
- 启动时会执行 `DataSeedService`，在表为空时播种菜单、角色、权限、会员等级、积分规则等基础数据。
- 开发库可执行 `server/demo-data.sql` 注入演示数据（幂等，可重复执行），覆盖门店、科室、医生、排班、预约、客户、积分、优惠券、消息等。

### 2.2 启动前端

```bash
cd panel/XianTong/client
pnpm -F @vben/web-antd run dev
```

- 默认监听 `5666`。
- 首次运行需先执行 `pnpm install`。

### 2.3 健康检查

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5666
curl -s -X POST http://localhost:8080/api/admin/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
```

预期：前端返回 `200`；登录接口返回 `{"code":0,...,"accessToken":"..."}`。

### 2.4 环境注意事项

- **CI 变量**：若 shell 中存在 `CI=true`，Playwright 的 `reuseExistingServer` 会变成 `false`，在前端已启动时报 `http://localhost:5666 is already used`。执行 E2E 时使用 `env -u CI`。
- **外部凭证**：未配置微信支付、腾讯云短信凭证时，后端自动降级到 mock 模式；真实支付回调与真实短信发送无法在本地闭环验证。
- **敏感配置**：支付、短信凭证放在本地 `.env.local`，不得提交到版本库。

### 3.1 Playwright 配置要点

配置见 [playwright.config.ts](../panel/XianTong/client/playwright.config.ts)。

- `testDir: ./e2e`，`baseURL: http://localhost:5666`。
- 全局 `globalSetup` 直接调用后端登录接口，将 token 注入 `localStorage` 后保存到 `.auth/admin-session.json`，其余用例复用登录态。
- 单条用例超时 30 秒，断言超时 5 秒；CI 下失败重试 2 次。
- 默认 `html` 报告输出到 `playwright-report/`，失败截图与 trace 输出到 `test-results/`。
- 用例通过 `e2e/fixtures/*` 复用登录态、vxe-table 网格定位与弹窗定位，避免各 spec 重复实现。

env -u CI pnpm exec playwright test -g "should display all expected table columns"

### 6.2 失败用例

**用例**：`e2e/system/user-management.spec.ts:55` — `should display role tags as blue Tags for each role (Req 7.14)`

**现象**：

```
Locator: row.locator('.ant-tag').nth(1)
Expected pattern: /ant-tag-blue/
Received string: "ant-tag ... ant-tag-geekblue mb-0.5"
```

**定位**：用户管理表格中，每行的 Tag 有两类：

- 角色标签：`color="blue"`（[user/index.vue 第 154 行](../panel/XianTong/client/apps/web-antd/src/views/system/user/index.vue#L154)）
- 授权门店标签：`color="geekblue"`（[user/index.vue 第 160 行](../panel/XianTong/client/apps/web-antd/src/views/system/user/index.vue#L160)）

用例用 `row.locator('.ant-tag')` 取到了行内全部 Tag，当一个用户既有角色又有授权门店时，第 2 个 Tag 是门店标签（geekblue），断言却要求它是角色标签的 blue。

**结论**：属于**用例断言范围过宽**，不是产品功能缺陷。页面实际渲染正确。

**建议修复**（待确认后执行）：把断言范围收敛到角色列单元格，例如给角色 Tag 增加 `data-testid="role-tag"`，或在用例中只断言 `.ant-tag-blue` 的数量与角色数量一致，不要遍历行内全部 Tag。
