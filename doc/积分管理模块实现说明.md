# 积分管理模块实现总结

## 📦 已实现的功能

### 1. 积分规则管理 API

**文件**: `server/src/main/kotlin/admin/service/AdminPointsService.kt`
**文件**: `server/src/main/kotlin/admin/route/PointsRoutes.kt`

实现了完整的积分规则 CRUD：
- ✅ `GET /api/admin/points/rules` - 获取所有积分规则
- ✅ `POST /api/admin/points/rules` - 创建新积分规则
- ✅ `PUT /api/admin/points/rules/{id}` - 更新积分规则

**功能特性**:
- 支持配置规则名称、类型（earn/spend）、动作类型
- 支持设置每日/每月上限
- 支持配置积分有效期（月）
- 支持启用/停用规则

---

### 2. 客户积分调整 API

**文件**: `server/src/main/kotlin/admin/route/BusinessRoutes.kt` (customerRoutes 函数)

实现了管理员手动调整客户积分：
- ✅ `PUT /api/admin/customers/{id}/points` - 手动增减客户积分

**功能特性**:
- 支持增加或扣减积分（正数/负数）
- 必须填写调整原因
- 自动记录操作人和操作时间
- 余额不足时拒绝扣减并返回错误提示
- 调整的积分默认有效期12个月
- 同时更新积分流水表和汇总表

---

### 3. 积分流水查询 API

**文件**: `server/src/main/kotlin/admin/service/AdminPointsService.kt`
**文件**: `server/src/main/kotlin/admin/route/PointsRoutes.kt`

实现了灵活的积分流水查询：
- ✅ `GET /api/admin/points/records` - 查询积分流水记录

**功能特性**:
- 支持按用户ID筛选
- 支持按来源类型筛选（checkin/consumption/admin_adjust等）
- 支持按日期范围筛选（startDate/endDate）
- 支持分页查询
- 返回完整的变动记录，包括变动前后余额、过期时间等

## 🗄️ 数据库表结构

使用现有的积分相关表：

### PointsRules (积分规则表)
```sql
- id: 主键
- ruleName: 规则名称
- ruleType: 规则类型 (earn/spend)
- actionType: 动作类型 (signup/consumption/profile_complete等)
- pointsPerUnit: 每单位积分
- unitDescription: 单位说明
- dailyLimit: 每日上限
- monthlyLimit: 每月上限
- validityMonths: 有效期(月)
- status: 状态 (1=启用 0=停用)
```

### PointsRecords (积分流水表)
```sql
- id: 主键
- userId: 用户ID
- changeAmount: 变动数量（正=获得，负=消耗）
- balanceAfter: 变动后余额
- sourceType: 来源类型
- sourceId: 关联ID
- expiresAt: 过期时间
- description: 说明
- createdAt: 创建时间
```

### UserPointsSummary (用户积分汇总表)
```sql
- id: 主键
- userId: 用户ID
- totalBalance: 当前总余额
- updatedAt: 更新时间
```

## ⚠️ 注意事项

1. **数据一致性**: 所有积分变动都在数据库事务中执行，确保流水表和汇总表的同步
2. **并发安全**: 使用 suspendTransaction 保证并发场景下的数据一致性
3. **审计追踪**: 管理员调整积分时会记录操作人用户名和调整原因
4. **余额校验**: 扣减积分前会检查余额，防止出现负数
5. **性能优化**: 使用 UserPointsSummary 表冗余存储余额，避免每次查询都计算总和
