# 本地启动脚本使用说明

**脚本位置**：`panel/XianTong/start-local.sh`  
**适用场景**：本地开发联调、管理端自测、小程序真机联调  
**维护提醒**：脚本参数或行为变更时同步更新本文档

---

## 1. 脚本作用

一条命令拉起管理端的两个本地服务，并在启动后做健康探活、打印访问地址：

| 服务 | 端口 | 启动方式 |
|------|------|----------|
| 后端 API（Ktor） | 8080 | 复用 `server/run-local.sh`，自动加载 `server/.env.local` |
| 管理端页面（Vben + Vite） | 5666 | `pnpm -F @vben/web-antd run dev` |

脚本不会修改任何配置、不会执行数据库迁移，只负责进程的启动、复用、重启与停止。

---

## 2. 前置依赖

| 依赖 | 版本/说明 |
|------|-----------|
| JDK | 21（Gradle 与后端要求） |
| pnpm | 已安装并完成 `client` 目录依赖安装 |
| PostgreSQL | 本地 5432，库与账号见 `server/.env.local` |
| Redis | 本地 6379，管理端会话与缓存使用 |

缺少依赖时脚本会明确报错，不会带着半启动状态继续。

---

## 3. 首次准备

```bash
cd panel/XianTong

# 1. 后端环境变量（首次）
cp server/.env.local.example server/.env.local
# 编辑 .env.local，按需填写微信、支付、短信、JWT 等凭证

# 2. 前端依赖（首次）
cd client && pnpm install && cd ..
```

说明：

- `server/.env.local` 是后端启动的**必需文件**，脚本检测不到会直接退出并提示路径。
- 未配置的凭证会自动降级为本地 mock（微信登录固定 `mock_openid_demo`、支付模拟成功、短信只打日志），仅限本地。

## 4. 参数说明

```bash
./start-local.sh [--restart] [--backend-only | --frontend-only]
```

| 参数 | 作用 | 默认 |
|------|------|------|
| 无参数 | 启动前后端，已在运行则复用 | 复用 |
| `--restart` | 先停掉**本项目启动的**服务再重启 | 关闭 |
| `--backend-only` | 只处理后端，不启动/重启前端 | — |
| `--frontend-only` | 只处理前端，不启动/重启后端 | — |
| `-h` / `--help` | 打印用法 | — |

参数可组合，例如 `--restart --backend-only` 表示只重启后端。`--backend-only` 与 `--frontend-only` 同时传入时两者都不启动。

---

## 5. 常用场景

```bash
# 日常启动：前后端一起起，已在跑就复用
./start-local.sh

# 只起后端（前端已在跑或不需要）
./start-local.sh --backend-only

# 改了后端代码或 .env.local，只重启后端
./start-local.sh --restart --backend-only

# 前端白屏/端口被自己的旧进程占用，只重启前端
./start-local.sh --restart --frontend-only

# 前后端都重来一遍
./start-local.sh --restart

# 查看用法
./start-local.sh --help
```

小程序真机联调：

1. 执行 `./start-local.sh`，记下输出的「局域网地址」，形如 `http://192.168.1.182:8080`。
2. 确认手机与电脑在同一 Wi-Fi。
3. 确认小程序 `app/XianTong/miniprogram/utils/request.ts` 的 `API_ORIGIN` 与该地址一致；换网后会变，需要同步修改。
4. 微信开发者工具中勾选「不校验合法域名、TLS 版本以及 HTTPS 证书」。

## 6. 日志与 PID 文件

| 路径 | 内容 |
|------|------|
| `panel/XianTong/logs/backend.log` | 后端启动日志、预检警告、接口异常堆栈 |
| `panel/XianTong/logs/frontend.log` | Vite 启动输出、编译错误 |
| `panel/XianTong/logs/backend.pid` | 后端监听进程 PID |
| `panel/XianTong/logs/frontend.pid` | 前端监听进程 PID |

- 每次启动会覆盖对应 `.log`（不是追加），需要历史日志请先另存。
- `logs/` 已在根 `.gitignore` 中忽略，不会提交。
- 排查问题优先看 `backend.log` 末尾的 `ERROR` 段与异常堆栈。

## 7. 启动/停止行为

**启动**

1. 检查目标端口是否已被监听：
   - 已监听且未加 `--restart` → 打印「复用现有服务」并跳过；
   - 已监听且加了 `--restart` → 校验该进程是否本项目启动（PID 文件 + 进程树），是则停止，否则跳过并提示。
2. 检查依赖文件（后端 `.env.local`、前端 `pnpm`），缺失即退出。
3. 拉起子进程，轮询端口就绪：后端最长等待 300 秒（首次编译较慢），前端 120 秒。
4. 就绪后写入 PID 文件、打印访问地址汇总。

**停止**

- 脚本在前台运行时按 `Ctrl+C`，会停止**本次脚本启动的**服务（端口最长等待 30 秒释放）。
- 复用来的服务不归本次脚本管理，`Ctrl+C` 不会停止它们。
- 想停掉之前启动的服务：再次执行 `./start-local.sh --restart` 会先停后启；只想停不启时，用 `lsof -nP -iTCP:8080 -sTCP:LISTEN -t` 找到 PID 后 `kill`。

## 8. 常见问题

| 现象 | 原因与处理 |
|------|------------|
| `端口 8080 被非本项目进程占用（PID xxx），跳过不停止` | 端口被其他程序占用，脚本出于安全不杀。先确认该进程是什么：`lsof -nP -iTCP:8080 -sTCP:LISTEN`，手动处理后重跑。 |
| `缺少 server/.env.local` | 执行 `cp server/.env.local.example server/.env.local` 后重跑。 |
| `未找到 pnpm` | 安装 pnpm 后执行 `cd client && pnpm install`。 |
| 后端启动超时 | 看 `logs/backend.log` 末尾，常见为数据库/Redis 未启动或端口被占。 |
| 小程序登录返回 `500 登录失败` | 看 `logs/backend.log` 是否有 `wechat code2session 失败 errcode=40125 invalid appsecret`，说明 `.env.local` 里 `WECHAT_APP_SECRET` 错误；修正后 `./start-local.sh --restart --backend-only`。未配置微信凭证时会走 mock，不会出现该错误。 |
| 小程序请求打不通 | `API_ORIGIN` 与本机当前局域网 IP 不一致（DHCP 换网会变）；以脚本输出的「局域网地址」为准。 |
| 每次重启签到码失效 | 未配置 `CHECKIN_SIGNING_SECRET`，后端每次启动生成随机密钥；需要固定码时在 `.env.local` 中配置稳定密钥。 |
| 前端端口被旧进程占着起不来 | `./start-local.sh --restart --frontend-only`。 |
| 跑 Playwright 报 `http://localhost:5666 is already used` | shell 中存在 `CI=true` 导致 Playwright 不复用已启动服务，执行时加 `env -u CI`。 |

## 9. 与手动启动的关系

脚本等价于以下手动操作，便于排查时对照：

```bash
# 后端（脚本内部）
cd panel/XianTong
bash server/run-local.sh          # 读取 server/.env.local 后执行 ./gradlew :server:run

# 前端（脚本内部）
cd panel/XianTong/client
pnpm -F @vben/web-antd run dev
```

健康检查（脚本会做端口探活，接口验证需手动）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5666
curl -s -X POST http://localhost:8080/api/admin/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
```

预期：前端 `200`；登录返回 `{"code":0,...}`。
