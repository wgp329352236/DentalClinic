# 就诊记录模块 - 快速参考卡

## 🎯 核心功能一览

### 用户端 API（小程序）

| 功能 | 接口 | 认证 | 状态 |
|-----|------|------|------|
| 查看就诊记录列表 | `GET /api/v1/medical-records` | JWT | ✅ |
| 查看就诊记录详情 | `GET /api/v1/medical-records/{id}` | JWT | ✅ |

### 管理端 API（后台）

| 功能 | 接口 | 权限 | 状态 |
|-----|------|------|------|
| 查看预约详情 | `GET /api/admin/appointments/{id}` | appointment:view | ✅ |
| 编辑病历摘要 | `PUT /api/admin/appointments/{id}/medical-record` | appointment:update | ✅ |

## 🔑 关键参数速查

### 用户端 - 就诊记录列表
```
GET /api/v1/medical-records?page=1&pageSize=20
Authorization: Bearer <user_token>
```

**返回字段**:
```kotlin
id: Long                    // 预约ID
appointmentDate: String     // 就诊日期 yyyy-MM-dd
startTime: String?          // 开始时间 HH:mm
endTime: String?            // 结束时间 HH:mm
clinicName: String          // 诊所名称
doctorName: String          // 医生姓名
doctorTitle: String?        // 医生职称
departmentName: String?     // 科室名称
diagnosis: String?          // 诊断结果
remark: String?             // 备注
consumptionAmount: Double   // 消费金额
completedAt: String?        // 完成时间
```

### 用户端 - 就诊记录详情
```
GET /api/v1/medical-records/1001
Authorization: Bearer <user_token>
```

**额外字段**（相比列表）:
```kotlin
clinicAddress: String?      // 诊所地址
doctorIntroduction: String? // 医生介绍
treatmentPlan: String?      // 治疗方案
arrivedAt: String?          // 到店时间
consumptionDetails: List    // 消费明细列表
```

### 管理端 - 编辑病历
```json
PUT /api/admin/appointments/{id}/medical-record
{
  "diagnosis": "龋齿补牙（左下第一磨牙）",
  "treatmentPlan": "树脂充填治疗，建议半年后复查"
}
```

**说明**:
- 两个字段均为可选
- 可单独更新其中一个
- 未传字段保持原值不变

## 🔍 业务逻辑要点

### 用户端查询逻辑
1. **只返回已完成的就诊记录** (`status = "completed"`)
2. **按就诊日期倒序排列**（最近的在前）
3. **自动聚合消费金额**（从 ConsumptionRecords 表）
4. **严格的数据隔离**（只能查看自己的记录）

### 管理端编辑逻辑
1. **支持部分更新**（可只传 diagnosis 或 treatmentPlan）
2. **保留未更新字段**（未传字段保持原值）
3. **记录审计日志**（操作人、操作时间）

## 🐛 常见问题

**Q: 用户看不到就诊记录？**
A: 检查预约状态是否为 "completed"，只有已完成的预约才会显示在就诊记录中

**Q: 消费金额为 0？**
A: 检查 ConsumptionRecords 表中是否有对应的记录（appointmentId 关联）

**Q: 编辑病历时提示"预约不存在"？**
A: 确认预约 ID 是否正确，以及该预约是否存在于数据库中

**Q: 新增字段后旧数据报错？**
A: SchemaUtils.create 会自动添加新列，确保重启服务让数据库迁移生效
